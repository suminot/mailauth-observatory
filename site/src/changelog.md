# 変更履歴

計測方法や集計定義の変更を記録する。数字が前月と比べて動いたとき、
**実態が変わったのか計測が変わったのか**を区別できるようにするためである。

この一覧は `mailauth changelog` が生成している（2026-11-07T22:14:20+00:00）。
版の変化は機械が検出するが、**それが数字にどう影響したかは人が書く。**
「解釈」の欄が空いている月は、まだ書かれていないということである。

## 2026-11

### この月の計測方法の変更（人が書いたもの）

- 送信の前段の判定に、Proofpoint・Mimecast・Barracuda・Cisco・Trend Micro などが送信のために SPF に載せる名前を足した（各社の資料にあるものだけ）。米国の送信の前段の企業数はこれで大きく増えている。
- DKIM の CNAME の行き先（SendGrid・HubSpot・Constant Contact・Salesforce など）と、SPF の include（KnowBe4・Mailgun・Oracle・国内の配信サービスなど）の判定を足した。配信サービスの企業数の増加はこれによる。
- 層を持たない推定（配信・DMARC 集計）を「配信に使われているサービス」「DMARC レポートの集計サービス」に分けた。ドメインの所有確認の TXT だけのものは送信の証拠として数えないようにした。
- DMARC の集計レポートの宛先が受け取りを認めるレコードを出しているかを、集計に足した。
- 実基盤の判定に、運営会社の資料で確かめた MX（iCloud+・Seznam・Daum など）を足した。
- SPF で DNS を引く項の数を、include と redirect の先まで引いて数えるようにした。上限 10 を超えるドメインと、先に SPF が無いドメインを集計に足した。
- SPF の最後の `all` の修飾子（-all・~all・?all・+all・無し）ごとの数を集計に足した`redirect=` で任せているものは任せた先の `all` で数える。
- DMARC を公開しているが、レコードが無効（2つある・p= が無いか不正）なドメインの数を、公開しているの内数として足した。
- DKIM を検出したドメインを、見つかった RSA 鍵のうち最も短いものの長さ（2048 以上・1024・1024 未満）で分けて数えるようにした。Ed25519 の鍵は長さを見積もらないようにした。
- DMARC を出しているが集計レポートの宛先（rua）が無いドメインと、そのうち p=none のもの、BIMI のうち証明書の場所を書いているものの数を足した。
- 国内企業の公式サイトの経路に、有価証券報告書の「公告掲載方法」に会社が書いている URL を足した（ページに商号が載っているものだけ）。国内で測れた会社数の増加はこれによる。
- ドメインの候補に、公式サイトのトップページがリンクしている別ドメインのうち、そのページのタイトルに商号があり MX があるものを足した。測るドメイン数の増加はこれによる。
- ドメインの候補に、国内企業が有価証券報告書の公告掲載方法に書いている自社ドメインを足した（公告の掲載を引き受ける事業者のドメインは除く）。
- 国内企業の公式サイトは、有価証券報告書に会社が書いた自社ドメインを優先するようにした。会社のものでないページ（企業情報サイトなど）が公式サイトとして入っていた企業がある。
- 米国企業の公式サイトは、会社が年次報告書に書いたサイトを優先するようにした（社名変更の前のサイトのままの企業があった）。前の公式サイトも候補のドメインとして残す。
- SPF の include・redirect の先のドメインが登録されていないもの、主ドメインの TXT の応答が 1,232 バイトを超える見積りのもの、DKIM の鍵が Ed25519 だけのもの、DMARC に RFC 9989 で無くなったタグがあるものの数を足した。
- 主ドメインの SPF が通すと書いた IPv4 アドレスが 65,536 を超えるドメインの数を足した（include の先は数えない）。
- 送信しているドメインのうち、大口送信者の要件（Gmail・Yahoo・Microsoft）のうち DNS で見られる部分（SPF・DKIM・DMARC）がそろっているものの数を足した。
- DMARC に RFC 9989 で入ったタグ（np=・t=y）があるドメインの数を足した。
- 前の月との差分に、両方の月に観測できた同じドメインでの DMARC の方針の移り変わりと、rua を足した・外した数を足した。pct= が 100 未満の quarantine から none への変化が、後退として数えられていなかったのを直した。
- DMARC の rua の宛先が例示用に予約された名前（example.com など）のドメインと、p=reject で rua があるドメインの数を足した。
- _domainkey.<ドメイン> を引くようにし、試したセレクタでは DKIM が見つからないドメインのうち、その配下に名前があるもの（試していないセレクタの鍵がありそう）の数を足した。
- 会社ごとに、受け取れる MX・SPF の送信元・DKIM の鍵がどこまでそろうかの段階と、公式サイトのドメインではなく別のドメインでメールを受けている会社の数を足した。
- ドメインごとに、会社と対応づけた根拠（会社が自分で書いた・証明書・会社の DNS・公式サイトのリンク先）と、メールに使っている証拠の段階を掛け合わせた数を足した。
- ドメインの候補に、公式サイトのドメインに MX が無い会社の、同じ名前の別の TLD のドメイン（MX があり、トップページのタイトルに商号があるもの）を足した。
- 同じ月の国内上場と米国上場の母集団を並べた表を、総括のページに足した（順位や優劣は示さない）。
- 日経平均株価の構成銘柄（225 社）を、国内上場の計測を測り直さずに別に集計するようにした。一覧は Wikipedia の記事（CC BY-SA 4.0）の証券コードを使う。
- 証明書の組織名でドメインを探す経路を、公式サイトのある会社にも広げた（月のあいだに補充で引いたものを使う）。見つけたサブドメインの数と、そのうち登録ドメインに DMARC があるものの数を足した。
- 国内上場の会社の国内子会社（有価証券報告書の関係会社のうち、gBizINFO に企業サイトの登録があるもの）を、上場会社とは別の母集団として測るようにした。上場会社の数字には混ぜていない。
- SPF に ptr があるドメインと、DMARC に失敗レポートの宛先（ruf）があるドメインの数を足した（宛先は出さない）。
- 公式サイトの証明書の記録（CT）に載っているメール用らしい名前のサブドメイン（news.・mail2. など）を、サブドメインの候補に足した（自分の MX か _dmarc があるものだけ測る）。効くのは次に CT を引く月からで、サブドメインの数はそれより前の月と比べられない。

## 記録の方針

集計定義を変えた場合、その月の数字と前月の数字は直接比較できない。
過去の集計は遡って作り直さず、履歴として残す。
